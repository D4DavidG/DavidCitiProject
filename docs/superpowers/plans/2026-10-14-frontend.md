# Frontend Implementation Plan (overnight build, 13 to 14 Oct)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan task by task (native execution, decided by David). Steps use checkbox (`- [ ]`)
> syntax for tracking.

**Goal:** A React website on top of the finished backend: the demo screens first and
complete, then the rest of `MVP.md`'s screens, all tested.

**Architecture:** A Vite single-page app in `frontend/`. It uses Material UI, React Router
with `HashRouter`, and react-responsive. It talks to the API only through
`src/services/request.js`, at `${VITE_API_URL}/api/tracker`. Session state lives in one
`AuthContext`. Each screen is a folder in `src/pages/`; shared pieces are in
`src/components/`.

**Tech Stack:** React 19, Vite 7, MUI 7, react-router 7 (`HashRouter`), react-responsive,
prop-types; Vitest, React Testing Library and `@vitest/coverage-v8`; Playwright 1.64.

**Spec:** `MVP.md` (screens and rules), `CLAUDE.md` ("The stack", §9 "Rules that don't
bend", §6 traps 2, 3, 5, 6, §10 React conventions), `docs/GUIDE.md` §6 (request flow), and
the API itself: `backend/tracker/api/routes.py` and `backend/tracker/services/views.py`
(exact JSON field names).

## Global Constraints

- One `request()` module for every backend call. A 401 is handled in one place (clear
  the session, go to `#/login`); the login call itself is exempt.
- The session is probed on load (`GET /auth/me`). Every `sessionStorage` access is
  wrapped in try/catch.
- No money arithmetic in the browser. Cents are only formatted, in
  `src/services/format.js`. Show whole dollars (`$12,500`).
- Wire names are camelCase, exactly as `services/views.py` emits them. Never rename
  fields in the client.
- Lists use the envelope `{items, page, pageSize, total, totalPages}`. Search and filter
  are server-side (`?search=`, `?status=`, `?page=`, `?pageSize=`).
- Errors arrive as `{error, field?}`. Show `error` in an MUI `Alert`. When there's a
  `field`, show it on that input (`helperText`, `error`, `aria-describedby`).
- On screen, use the brief's words: **Deliverables** (API: milestones) and **Resources**
  (API: assignments/bookings).
- Function components, `.jsx`, PropTypes and JSDoc on components. No TypeScript.
- Folder names to avoid (gitignored): `lib`, `assets`, `build`, `dist`, `env`, `logs`,
  `tmp`, `coverage`. Check new paths with `git check-ignore -v`.
- `npm audit --audit-level=high` must pass (CI runs it). Check after every install.
- Light theme only (dark mode is out of the MVP). Note the contrast ratio next to each
  colour token.
- The backend is finished. Change it only to fix a bug the frontend exposes, test first,
  and log it in the report.

## Review Focus

1. **Token expires mid-session:** the next call gets 401. Expect one redirect to login
   and a "session expired" message, not a loop or a blank page.
2. **Aurora waking up:** the first call can take 15 s or return 503 "The database is not
   ready". Expect a loading state, then a readable error with a Retry button.
3. **Phone width (375 px):** every page usable. Tables become cards, the allocation grid
   scrolls sideways, and the sidebar becomes a drawer.
4. **Wrong role:** an employee who types `#/dashboard` gets a "not available for your
   role" page, not a crash. The server's 403 shows as a message.
5. **Empty data:** a manager with no projects, or a week with nobody over capacity, shows
   a clear empty state ("No one is over capacity this week"), never a blank table.
