## Task 2. The scan in the tour, red first

Code (test code, so it is the "test" step), `frontend/e2e/tour.spec.js`:

- `import AxeBuilder from '@axe-core/playwright'`.
- Header comment: one line, "Also runs axe on every screen: serious or critical WCAG A/AA
  problems fail the test."
- `const TAGS = ['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'] // every WCAG 2.0-2.2 A and AA rule axe has`
- `const FAILING = ['serious', 'critical']`
- ```js
  // Runs axe on the page as it is now and adds one line per serious or critical problem.
  async function scan(page, where, problems) {
    const { violations } = await new AxeBuilder({ page }).withTags(TAGS).analyze()
    for (const v of violations.filter((x) => FAILING.includes(x.impact))) {
      problems.push(`${where}: ${v.id} (${v.impact}, ${v.nodes.length} elements: ${v.nodes[0].target.join(' ')})`)
    }
  }
  ```
- In the role-by-width test: `const problems = []`. Sign-in page: split `signIn` so the
  test can scan between `page.goto('/')` + the Username field being visible and filling
  it; simplest: give `signIn(page, username, beforeSignIn)` an optional callback, or
  inline `await page.goto('/'); await expect(page.getByLabel('Username')).toBeVisible();
  await scan(page, 'sign-in page', problems)` before `signIn` (which then does its own
  `goto`). Prefer the inline version: no new parameter.
- In the screen loop, after `await expect(page.getByRole('tooltip')).toHaveCount(0)` and
  before the overflow check: `await scan(page, screen, problems)`.
- After the loop, at phone width only (`if (viewport === 'phone')`): go to the role's first
  screen, click `getByRole('button', { name: 'Open menu' })` (`AppLayout.jsx:55`), wait
  for the `navigation` "Main menu" to be visible, `scan(page, 'phone menu', problems)`,
  press Escape.
- At the end: `expect(problems, 'accessibility problems (axe, serious or critical)').toEqual([])`
  after the existing overflow assertion.
- Test title: `` `${role} at ${viewport} width: every screen renders without sideways scrolling or serious accessibility problems (axe)` ``.
